# ALL-IN (working title)

2D pixel-art single-player game (Unity 6000.3.21f1 LTS, URP 2D). One life, age 21 → 70: a young man just discharged from Korean military service starts with a 20,000,000 KRW service savings payout, earns cash from day labor, and throws it at coin futures, lotto, gambling and hold'em tournaments hoping to get rich. Odds are honest: ~99% fail. Going bankrupt does NOT reset to discharge day (that rule is discarded): he ships out on a 6-month ocean-going fishing boat (paid, body max shrinks, health debt) and comes back to try again. At 70 the ending depends on the asset bracket. Only "새 인생" (a brand-new game) resets. The point is the emotional loop — liquidation shame → next day's labor → dopamine when luck turns → "hope circuit" fantasies. No IAP. **No undo / no load — real life has no load button. Never add save slots or rewind as a convenience feature.** No meta progression except a codex of scenes witnessed.

Implemented now: restaurant job, coin futures, lotto, hold'em tournament minigame (standalone), bankruptcy + ship + health (v0.4 stage 1), v0.5: the random "무조건 승리" button (coin watch scene + hold'em called all-ins; chance q = 0 until the user picks it), pixel-art protagonist walking a street, clothes / car as pure consumption, companions as a picture slot only. Planned extension points only (do not build): warehouse/construction jobs, stocks, legal/illegal gambling, consumption effects, romance, family systems, real estate, gift tax, the 70-year ending. Direction and roadmap: `md/VISION.md`.

## Core rules
- Assemblies: `AllIn.Core` and `AllIn.Holdem` are pure C# (**no UnityEngine**); `AllIn.Game` is presentation only — **never re-derive rules there**, ask Core. All strings in `Core/Texts.cs`, numbers in `Rules.cs`.
- Randomness: only `AllIn.Core.IRng` / `Xoshiro128`, seed-injected. `System.Random` and `UnityEngine.Random` are banned.
- Money: `long` KRW, shown via `Fmt.Won`. Saved numbers must be integral.
- **1 action = 1 slot** (job, rest/sleep, coin open, coin close). Lotto purchase and viewing the coin screen are free.
- UI is built in code at runtime; no hand-edited prefabs/scenes.
- Tests: NUnit `[Test]` only in Core/Holdem tests; names state intent.

## Commit rules
- Windows: write the message to a file and `git commit -F .git/COMMIT_MSG` (never inline). A stage is done when harness test + sim pass, Unity compiles with 0 errors, and STATUS is updated.
- Before every commit, if ProjectSettings/UnityConnectSettings.asset is modified, run `git checkout --` on it. Unity Services must stay off; the editor rewrites this file during builds.

## Don't
- Add debt/loans, stocks, loading/construction jobs, or hook hold'em into the loop (extension-point comments only).
- Polish or add copy — placeholder strings only. All player-facing text lives in `Core/Texts.cs` (the user replaces copy later).
- Tweak balance on your own. Numbers come from DESIGN.md; if a sim acceptance criterion fails, change DESIGN.md first and log why.
- Use `System.Random`, `UnityEngine` in Core/Holdem, any undo/rewind UI, or hand-edit prefabs/scenes.
- Build hold'em cash games, antes, rule variants, real multi-table, or a GTO solver.
