### B5. 코인 선물 — 청산 체인 (v0.3)

> "청산가 1cm 앞에서 ㄹㅇ 기도메타할떄 기분 .. 청산후 분노의 100배 뱃 .. 나머지은행계좌 업비트에 입금했는데 24시간 룰떄문에 전송도못해서 안절부절할떄 그모습 .. 다음날입금했는데 청산됬는데 본절가 와있을떄 그 좌절 .."
>
> 네 장면(관전·분노·24시간 룰·본절)은 아래 규칙에서 자연 발생해야 한다. 특정 날 청산시키는 등 스크립트 강제 금지. 이 개편은 신규 기능이라 "수치 동결" 예외 — 기존 튜닝 후보(멘탈 스파이럴, 로또 −1)는 여전히 손대지 않는다.

**돈의 세 칸** — 은행 / 국내 거래소(원화·현물, 가칭) / 해외 선물 거래소 지갑(가칭). 실제 브랜드명 사용 금지, `Texts.cs`에 임시 이름.

|---|---|
| 시작 자금 | 20,000,000 전액 은행 (Day 1 새벽, 오프닝 텍스트 후) |
| 월세·식비·알바 일당·로또 | 전부 은행에서 나가거나 은행으로 들어옴 |

Day 1 새벽에 은행→국내→해외까지 옮겨야 Day 2 같은 슬롯부터 첫 거래가 가능하다 — 의도된 첫 경험.

**가격 · 서브틱 경로**

| 항목 | 값 |
|---|---|
| 가능 슬롯 | 전부 (열기·닫기 각각 슬롯 1개 소비, 밤이면 밤샘) |
| 시작가 | 100,000,000원 |
| 슬롯 틱 수익률 | 로그수익률 r = t(df=3) × 0.010, \|r\| ≤ 0.25 — **기존과 동일한 분포**(슬롯 종가 분포는 불변) |
| 서브틱 경로 | 슬롯의 r을 서브틱 12개로 분해: 증분 t(df=3) × (0.010/√12)를 **서브틱 전용 RNG 스트림**(시장 RNG와 분리)으로 12개 샘플한 뒤, 합이 r이 되도록 선형 보정(브라운 브리지 근사). 경로는 슬롯 시작 시 미리 생성(되돌리기 없음과 일관) |
| 청산 판정 | 경로 전체(꼬리 포함) 대상 — 포지션 보유 슬롯에서만 계산. 종가가 회복했어도 경로 중 청산가를 찍으면 청산. 종가만으로는 청산이 아니었을 경우 "꼬리 청산" 플래그 기록 |
| 가격 반올림 | 매 서브틱 원 단위 정수 |
| 레버리지 | 5 / 10 / 25 / 50 / 100 |
| 증거금 투입 | 해외 지갑 잔고의 0~100% (슬라이더) |
| 포지션 | 1개만 |
| 수수료 | 진입·종료 각각 명목 × 0.05% |
| 청산 | 미실현손실 ≥ (증거금 + 추가 증거금) × 0.9 → 소멸(회수 0) |
| 증거금 추가 | 해외 지갑 잔고에서 추가 투입 가능. 명목·수량은 불변, **청산가만 재계산**되어 남은 서브틱에 적용 |
| 예약 주문 | 없음 |

**정산식 (해석):**
- 투입액 C(해외 지갑에서 빠짐), 명목 N = C × 레버리지, 진입 수수료 = N × 0.0005 → **증거금 M = C − 진입 수수료**. 수량 q = N / 진입가(고정, 이후 변하지 않음).
- 미실현손익 = q × (현재가 − 진입가) × (롱 +1 / 숏 −1).
- 증거금 추가 A(해외 지갑에서 빠짐, 누적 가능, ΣA)는 M에 더해지되 N·q는 그대로 — 청산 기준 손실 = (M + ΣA) × 0.9.
- 청산가(롱) = 진입가 × (1 − 0.9(M+ΣA)/N), (숏) = 진입가 × (1 + 0.9(M+ΣA)/N). ΣA가 바뀔 때마다 재계산.
- 수동 종료(관전 중 손절 포함): 종료 수수료 = q × 현재가 × 0.0005, 돌려받는 돈 = max(0, M + ΣA + 미실현손익 − 종료 수수료) → **해외 지갑으로**.
- 실현손익(통계) = 돌려받은 돈 − (C + ΣA). 청산이면 −(C + ΣA).
- 100배면 왕복 수수료가 투입액의 10% — 의도.
- 청산 서브틱이 밤/새벽 슬롯으로 넘어가는 순간이면 E2, 그 외는 E1. 잠든 상태에서는 관전 없이 곧장 E2(꼬리 청산이라도 동일).

### B5e. 가격 드리프트 보정 (v0.5 회신, 2026-09-30)
- 측정(`sim drift` → `md/SIM_DRIFT.md`): 틱 로그수익률 r = t(3)×0.010(|r| ≤ 0.25)의 E[e^r] = **1.0001353 ± 0.0000053**(1,000만 샘플, z = 25) → 마팅게일이 아니었다(30일 150틱이면 가격 기대치 약 +2.05%). 코인 전용 대조(E 봇 전략만, 알바·로또·굶주림·무조건 승리 없음, 30일, 5,000런)에서 롱 − 숏 최종 총자산 = **+5.87M원 (z = 5.0)**: 롱이 유의하게 유리했다.
- 보정: 캡을 씌운 틱 로그수익률에서 상수 **c = ln E[e^r] = 0.0001353**을 뺀다(`Rules.CoinDriftC`, 고정 시드 몬테카를로 1회 측정값). 서브틱 경로는 보정된 슬롯 r을 합으로 갖는다. 보정 후 E[e^(r−c)] = 1.0000000 ± 0.0000053, 롱 − 숏 = −0.10M원 (z = −0.09).
- 캡(±0.25)은 원래 tick 값에 걸리고 c는 그 뒤에 뺀다(따라서 최종 틱은 [−0.25−c, 0.25−c]).

### C-v2. 올인 or 폴드 + 승수 사다리

**의도 (사용자 원문 그대로)**
> "실제로 플레이하는건 너무 복잡하고 사용자가 홀덤을 추가로 공부해야 성과를 낼 수있는것 같아.
> 1. 살인적인 블라인드는 유지
> 2. 사용자는 올인 or 폴드만
> 3. 대회의 규모에 따라 몇연승하면 머니인,파이널테이블,우승이 정해짐. 예를들어 동네 홀덤펍에서 큰 대회 참가권을 따는건 3연승, 규모가 큰 대회에서 머니인하는건 5연승, 파이널테이블은 6연승, 우승은 8연승 처럼. 한번지면 탈락 or 상대의 스택만큼 칩 감소"

설계 메모: N승 ≈ 칩 2^N배 ≈ 필드 2^N명 중 1등이므로 연승 수는 토너먼트 규모와 수학적으로 대응한다. "탈락 or 칩 감소"는 커버 여부로 둘 다 적용한다.

**핸드 루프** (전부 임시값)
| 항목 | 규칙 |
|---|---|
| 스택 | 시작 15bb = 1,500칩. 칩 단위로 저장, 표시는 bb. bb(레벨 L, 0부터) = 100 × 2^L |
| 블라인드 레벨 | 6핸드마다 +1(bb 가치 2배 → 내 스택의 bb 수 절반). 재입장해도 핸드 카운트·레벨은 이어진다 |
| 포지션 | 핸드마다 순환: UTG·UTG·UTG·MP·MP·CO·BTN·SB·BB(9-max, 1핸드 = 1칸). 내 뒤에 남은 상대 = 8 − 인덱스(UTG 8명 … SB 1명, BB 0명) |
| 선택 | [올인] / [폴드]만. 핸드 시작 시 카드 2장 공개 |
| 폴드 | SB면 0.5bb 손실, 그 외 무손실 |
| BB (rev.2) | BB 자리는 **1bb 앤티를 추가로 낸다**(BB 1 + 앤티 1 = 2bb). 앞 좌석 8명이 순서대로(UTG·UTG·UTG·MP·MP·CO·BTN·SB) 스틸 올인 여부를 정한다: 상대 핸드 상위 % ≤ `PushFoldTable.PushPercent(그 좌석 포지션, 유효스택bb) × 성격 배율`. 첫 번째로 지른 사람이 있으면 나는 **[콜(올인)] / [폴드]**: 폴드 −2bb(BB + 앤티), 콜은 일반 콜과 같은 승패·커버·승수 규칙. 아무도 안 지르면 선택 없이 +0.5bb(SB 획득; 내가 낸 BB·앤티는 돌려받음) |
| 상대 | 내 뒤 좌석 1…n(좌석 번호 순으로 행동). 좌석 성격은 대회 안에서 고정 |
| 상대 스택 (rev.2) | 핸드마다 좌석별로 **평균 스택 × 로그정규(중앙값 1.0, σ 0.5)**(임시). 평균 스택 = 시작 칩 × 필드 크기 ÷ 남은 인원(남은 인원 = ceil(필드 ÷ 2^승수), 최소 1). 내 스택과 무관 |
| 콜 판정 | 콜 조건: 상대 핸드 상위 % ≤ `PushFoldTable.CallPercent(내 포지션, 유효스택bb) × 성격 배율`(100% 상한, 유효스택 = min(양 스택)/bb). 내 포지션이 SB이면 SB 행 |
| 첫 콜러 | 순서대로 첫 콜러가 나오면 나머지는 폴드 |
| 스틸 | 아무도 콜 안 함: 팟 획득 = SB 0.5 + BB 1 + 앤티 1 = **+2.5bb**(내가 SB면 이미 낸 0.5bb를 빼고 순 +2.0bb). 승수 변화 없음 |
| 콜됨 | 양쪽 카드 즉시 공개 → 플랍(즉시) → 턴 0.9초 → 리버 1.5초 → 판정 |
| 승 | 승수 +1, 스택 += min(내 스택, 상대 스택). 상대는 탈락 → 그 좌석에 새 상대(성격 재추첨) |
| 패 | 내 스택 > 상대 스택: 상대 스택만큼 잃고 계속(승수 유지, 상대는 두 배로 남음). 내 스택 ≤ 상대 스택: 탈락 |
| 무승부 | 스플릿, 변화 없음 |
| 자동 올인 | 스택 < 1bb이면 선택 없이 올인 |
| 콜 시 블라인드 | SB/BB로 낸 돈은 올인에 합산된 것으로 보고 따로 정산하지 않는다 |

**사다리 경제 확정 (사용자 승인 2026-10-01, sim 검증 `md/SIM_LADDER_ECON.md`)**: 원칙 = 필요 승수 ≈ log2(필드). 펍 3승 유지·참가비 30,000 → **25,000**. 새틀라이트 필드 16 → **64**, 필요 승수 4 → **6**(남은 인원 표시·버블 기준도 64 기준: 남은 인원 = ceil(64 ÷ 2^승수), 버블 = 5승). 참가비는 사용자 제안 110,000이 목표(차트 봇 ROI −10~0%)를 벗어나(새틀 차트 −15.0%) **100,000으로 조정**(필요 승수는 고정): 그러면 펍 시트 가치(= 새틀 참가비 100,000)도 함께 내려가 네 칸 모두 목표 안 — 펍 차트 −9.4% / 직감 −21.8%, 새틀 차트 −6.5% / 직감 −60.5% (무조건 승리 3% 포함, 1,000런). 메인은 변경 없음. 펍 차트 −9.4%는 목표 하한(−10%)에 가깝다 — 시드에 따라 흔들릴 수 있음.

**결과(TournamentResult v2)**: 최고 단계(Stage), Wins, Hands, Steals, Reentries, BadBeats, BubbleReached, Prize + 통계(CalledAllIns, CalledWins, Folds).

**HUD (StudyLevel)**: 0 = 내 카드·스택(칩 더미)·승수 / 1 = 스택 bb·다음 블라인드까지 핸드 / 2 = 포지션 + 내 뒤 상대 수 / 3 = 콜 시 양쪽 에퀴티 % / 4 = 푸시 권고(현재 bb·포지션의 `PushFoldTable.PushPercent`) + 내 핸드 O/X. 좌석별 성향 메모는 미구현(Open design).

**sim H (보고 전용, 수치 변경 금지)**: 대회별 × {직감 봇, 차트 봇, 랜덤 봇} × 1,000회. 직감 봇 = 포켓페어·A 포함·브로드웨이 두 장만 올인. 차트 봇 = 권고 그대로. 랜덤 봇 = 50% 올인.

### C4. 상대 AI
**프리플랍**
- 169 핸드 클래스 순위(1~169, 랜덤 1:1 대비 에퀴티 순) 내장.
- 유효스택(bb) = min(내 스택, 최대 상대 스택) / BB.
- 유효스택 ≤ 15bb → 푸시/폴드: 표(포지션 UTG·MP·CO·BTN·SB × 3·5·7·10·15bb → 푸시 상위 %, 오픈 푸시에 대한 콜 상위 %). 단조성: 후위일수록·짧을수록 넓게.
- 유효스택 > 15bb → 오픈 2.5bb, 림프 없음. 오픈 %: UTG 12 / MP 15 / CO 25 / BTN 42 / SB 36.
- 오픈 앞에서: 상위 5% 3벳(3×) / 다음 8% 콜 / 나머지 폴드. 3벳 받으면 상위 4% 올인·콜 / 나머지 폴드.
- 스택 ≤ 2 × 팟이면 공격 액션은 올인.
- 포지션 매핑(9-max, 버튼 기준): BTN, SB, BB, CO(버튼 오른쪽 1), MP(오른쪽 2~3), 나머지 UTG. BB는 방어(콜 레인지 = 콜 표/오픈 앞 규칙).

**포스트플랍**
- 에퀴티: 몬테카를로 400회(상대 핸드 랜덤·남은 보드 랜덤, 상대 수 = 남은 상대 수). 스트리트당 1회 계산, 캐시.
- eq = 에퀴티, po = 콜액 / (팟 + 콜액).
- 체크로 넘어옴: eq ≥ 0.62 → 벳 2/3팟 / eq ≥ 0.45 → 체크 / 그 외 체크(p_bluff 확률로 벳 1/2팟).
- 벳 받음: eq ≥ po + 0.20 → 레이즈 2.5× / eq ≥ po + margin → 콜 / 그 외 폴드.
- 스택 ≤ 2 × 팟이면 레이즈 대신 올인.

**성격 4종**

> 사용자 원문(2026-09-30)은 `md/VISION.md`의 "v0.5 사용자 원문"에 그대로 있다. 수치는 모두 ⟨임시⟩.
> 사용자가 이번 지시에서 소비(옷·자동차)·가정 그림 자리를 직접 요청했으므로 CLAUDE.md "Don't"의 소비 항목보다 이 Part가 우선한다. 이성·가정 **시스템**(로드맵 ④)은 여전히 선반영하지 않는다.

### E1. 무조건 승리 — 공통 규칙
- 플레이어의 "운". **순수 랜덤**: 기도·종교·mental·스탯·잔고 어느 것으로도 확률이 오르지 않는다(v0.3 "기도 효과 0" 유지). 기도와 버튼이 같은 화면에 있어 생기는 체감 상관관계는 의도다.
- **쌓이지 않는다.** 그 순간에만 뜨고, 그 이벤트가 끝나면 사라진다. 저장·쿠폰화 없음.
- **베팅이 확정된 뒤에만** 뜬다(코인: 포지션 진입 후 / 홀덤: 콜 성립 후). 금액·레버리지를 정하는 화면에서는 절대 뜨지 않는다.
- 뜨면 **반드시 눌러야 진행**된다(누르는 행위가 의식). 사전 예고 없음. 금색 버튼 + 빛 연출, 문구는 `Texts.cs` 임시.
- 보상 상한은 "건 돈의 2배".
- 발동 판정은 전용 PRNG 스트림(`luck`)에서 뽑는다. 기도 횟수·mental·그 무엇과도 독립. q = 0이면 스트림을 **한 번도 뽑지 않는다**(비교용 sim·테스트는 q를 0으로 두고 기존 수치를 재현한다: `Loop.DefaultLuckQCoin`, `LadderConfig.DefaultLuckQ`).
- **q 확정(사용자, 홀덤 2026-09-30 · 코인 2026-10-01): 홀덤 3%(콜 성립 올인당), 코인 1%(관전 1회당).** 코인은 처음 2%였으나 드리프트 보정 후 30,000런 순효과(E 봇 − 코인 끈 대조)가 q=0 −1.17M / 1% −0.51M / 2% +0.17M / 3% +1.08M(유의한 양수)라 1%로 내렸다: 1%는 점추정이 음수 — 버튼이 있어도 코인은 평균적으로 지는 게임. 신뢰구간 엄격 기준(0%)은 기능 제거와 같아 채택하지 않음. E 봇은 극단 전략이라 일반 플레이어의 이득은 이보다 작다. 홀덤 5%는 펍 평균 콜 올인 4.5회 기준 약 5판 중 1판 노출이라 "가끔" 감각보다 잦아 3%(약 8판 중 1판)로 낮췄다. (`Rules.LuckQCoin`, `HoldemRules.LuckQHoldem`)
- 정산표(E7)에 "무조건 승리 M회"를 "기도 N회" 바로 옆에 표시. 홀덤 결과 화면에도 M회.
- **로또는 적용 제외.**

### E2. 홀덤 (사다리 v2)
- 판정 시점: 플레이어가 관여한 **콜 성립 올인**(내 푸시가 콜됨 / 내가 BB에서 콜)마다, 카드 공개 직전 확률 `q_holdem`으로 발동. 스틸 성공·폴드·FreeBlind에는 발동하지 않는다.
- 효과: 그 올인은 플레이어 승리. 보드는 "플레이어가 이기는 런아웃"을 남은 덱에서 조건부로 생성(원래 보드가 이미 이기면 그대로 둔다). 무승부도 승리로 바뀐다. 승수 +1, 칩 정산은 일반 승리와 동일. 배드빗 판정에서 제외.
- 판정은 콜이 확정된 뒤에만 이뤄지므로 결정 화면에는 절대 표시되지 않는다.

### E3. 코인 선물
- 판정 시점: **관전 장면**(손실 ≥ 증거금 70%)이 시작될 때 확률 `q_coin`(관전 1회당). 알바 중이어도 관전 화면에 뜬다(누르기만 가능). 잠든 슬롯·승선 중·"못 일어나는" 슬롯에는 뜨지 않는다(관전 자체가 없음).
- UI 흐름: 관전이 트리거 서브틱에 닿으면 재생이 멈추고 금색 버튼이 뜬다. 누르면 진행.
- 효과: 남은 서브틱 경로를 포지션 방향으로 반등하는 경로(현재가 → 목표가, 단조)로 교체하고, 경로 끝에서 **ROE +100%**(총 증거금 M+ΣA만큼 평가이익)로 **자동 종료**한다. 청산가 판정은 발동 이후 없다. 종료 수수료는 차감(`ClosePositionAt`). 레버리지와 무관하게 보상은 "증거금 2배 − 종료 수수료". 목표가 = 진입가 ± (M+ΣA)/수량.
- 트리거 서브틱이 곧바로 청산가 너머인 갭이어도 발동이 우선한다(그 서브틱의 청산 판정을 유보).
- 유령(E8)·분노 판정 대상 아님(청산이 아니므로). 종료가 이익이면 일반 종료처럼 mental·희망회로 규칙을 탄다.
- 헤드리스(sim/테스트)는 발동 시 자동으로 "누른" 것으로 처리한다.

### E4. q 밸런싱 (sim으로 추천, 결정은 사용자)
- 원칙: 버튼 포함 EV가 버튼 없는 EV보다 좋아지되 **여전히 음수**(하우스 엣지 유지).

- 매장 4단계: 중고 경차 500만 / 국산 중형 3,000만 / 수입 세단 8,000만 / 슈퍼카 3억 ⟨임시⟩. 한 대만 보유(구매 시 기존 차가 있으면 거절).
- 보유 시 집 앞 주차, 이동할 때 캐릭터 대신 차가 달린다(연출만).
- 월 유지비 = 차량가 × 0.5%, 월세와 같은 날(nextRentDay) 은행에서 차감. **파산 판정·미납 계산에는 포함하지 않는다.** 은행 잔고가 모자라면 차감하지 않고 한 줄 알림만(부채 없음).
- 매각: 차량가의 60%로 즉시 은행 입금.

### E9. 가정 (그림 자리만)
- SaveData `companions`(배우자·자녀 슬롯) 리스트만. 채울 방법 없음. 방·거리 장면에서 companions가 있으면 옆에 그리는 렌더 경로만 구현. 에디터 전용 디버그 메뉴로 켜 본다. 실제 이성·가정 시스템은 로드맵 ④.

### E10. 세이브
- SaveData `version` 1 → 2. 외형(레이어 선택), 보유 의류, 착용 세트, 차량, companions, luck RNG 상태 추가. 이전 세이브는 기본 외형·의류 1벌·차 없음으로 마이그레이션하고 luck 스트림은 seed에서 유도한다.

### E11. 구현 해석 (v0.5, 명세가 침묵하던 부분 — 사용자 확인 필요)
1. **코인 발동 시점**: 관전 걸음(walk)이 만들어질 때 한 번 굴린다(잠·승선·"못 일어나는" 슬롯은 굴리지 않음). 버튼은 관전이 **트리거 서브틱에 닿은 직후** 뜬다 — 그 서브틱이 이미 청산가 너머인 갭이어도 청산 판정을 유보하고 누르게 한다. 트리거가 12번째 서브틱이면 그 서브틱이 종가가 된다.
2. **목표가**: 진입가 ± (M+ΣA)/수량(롱은 올림, 숏은 내림). 종료 수수료는 `ClosePositionAt`이 그대로 차감하므로 실현손익 = 증거금 증가분 − 진입·종료 수수료. 반등 경로가 끝나면 그 슬롯의 종가가 목표가가 되고, 시장 가격은 거기서 다음 슬롯을 이어간다.
3. **홀덤 발동 시점**: `Ladder.Showdown`(내 푸시가 콜된 경우 + BB에서 내가 콜한 경우) 안에서 한 번. 원래 보드가 이미 이기면 보드를 바꾸지 않는다(`LuckFlipped=false`). UI는 콜 확정 후 카드 공개 직전에 버튼을 띄운다.
4. **luck 스트림**: 코인 = `Loop.LuckRng`(seed ^ 상수, SaveData `luckRngState`), 홀덤 = `Ladder.LuckRng`(없으면 대회 스트림 사용, 게임·sim은 항상 별도 지정).
5. **옷 아이템 구조**: id = 부위×100 + 등급×10 + 변형. 변형 = 모양(그림), 등급 = 원단(팔레트)·가격. 세 등급 × 상의 5·하의 3·신발 2·액세서리 2. 가격 = 등급 기준가 × 부위 계수 × (1 + 0.1×변형), 등급 상한(5만/50만/500만) 적용. 시작 세트(기본 등급 변형 0의 상의·하의·신발)는 0원으로 보유.
6. **장소 매핑**: 알바→식당 / 코인·은행(거래소)→은행·거래소 / 로또→복권방 / 옷가게·자동차→해당 가게 / 옷장·쉬기·잠·검진→집 / 홀덤펍→건물만 있고 한 줄 알림(홀덤을 루프에 잇지 않음). 집에 있을 때만 방 장면, 그 외엔 거리 장면. `Loop.MoveTo`는 시계·슬롯·RNG에 손대지 않는다.
7. **자동차**는 총자산에 넣지 않는다(순수 소비). 월 유지비는 월세 직후에 은행 잔고만큼 빼며, 모자라면 한 줄 알림만(부채·파산 계산에 미포함). 차가 있으면 이동이 자동차 주행(연출만).
8. **원양어선 복귀**: `place`는 집으로 리셋. 승선 장면(검은 화면)에서는 거리·캐릭터·동반자를 그리지 않고 간단한 배 그림을 띄운다.
9. `Pose`는 UnityEngine.Pose와 충돌해 `DollPose`로 이름 붙였다.
